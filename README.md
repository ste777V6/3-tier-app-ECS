# Infrastructure: 3-tier Quiz App on ECS Fargate

Terraform for the DevOps Learning Platform (quiz app): a React frontend and a Flask backend on ECS Fargate, with PostgreSQL on RDS.

## Architecture

```
                 Internet
                    │  HTTPS (ACM cert), HTTP → HTTPS redirect
                    ▼
        ┌────────────────────────┐   public subnets
        │   Application LB       │
        └───────────┬────────────┘
                    │ :80  (health check /health)
  ┌─────────────────▼──────────────────────────────────── private subnets ──┐
  │  ┌──────────────────────┐   Service Connect   ┌──────────────────────┐  │
  │  │ frontend (ECS)       │ ──────────────────► │ backend (ECS)        │  │
  │  │ React + Express      │  http://backend:8000│ Flask + gunicorn     │  │
  │  │ proxies /api/*       │  (private, in-VPC)  │                      │  │
  │  └──────────────────────┘                     └──────────┬───────────┘  │
  └──────────────────────────────────────────────────────────┼──────────────┘
                                                             │ :5432
                                                             ▼
                                              ┌──────────────────────────┐
                                              │ RDS PostgreSQL           │ database subnets
                                              └──────────────────────────┘ (no internet route)
```

- **The browser only talks to the frontend.** The frontend's Express server proxies `/api/*` to `BACKEND_URL`, so the backend has no public endpoint at all.
- **Frontend → backend uses ECS Service Connect.** The backend is published in a Cloud Map namespace as `backend`. ECS injects an Envoy sidecar into every task, and the frontend reaches the backend at `http://backend:8000`. There's no extra load balancer, and traffic never leaves the VPC.
- **Security groups enforce the chain** internet → ALB → frontend → backend → RDS. Each tier accepts traffic only from the tier in front of it.
- **Database credentials:** the `postgresql://` connection string is generated by Terraform, stored in Secrets Manager, and injected into the backend as `DATABASE_URL`.

## Layout

```
Infra/
├── backend.tf          # S3 remote state (Terraform backend, not the app!)
├── provider.tf
├── variables.tf
├── terraform.tfvars
├── outputs.tf
│
├── networking.tf       # module "networking"
├── security.tf         # module "security"
├── alb.tf              # module "alb"
├── database.tf         # module "database"
├── ecs_cluster.tf      # module "ecs_cluster"
├── ecs_backend.tf      # module "backend"   (uses modules/ecs_service)
├── ecs_frontend.tf     # module "frontend"  (uses modules/ecs_service)
│
├── scripts/seed-db.ps1 # one-off task that loads the quiz questions
├── tests/              # `terraform test`: full plan with mocked AWS
└── modules/
    ├── networking/     # VPC, public/private/database subnets, NAT
    ├── security/       # ALB, frontend, backend, RDS security groups
    ├── alb/            # ALB, listeners, blue/green TGs, ACM, log bucket
    ├── database/       # RDS PostgreSQL + connection-string secret
    ├── ecs_cluster/    # cluster + Service Connect namespace
    └── ecs_service/    # ONE service: ECR, logs, IAM, task def, service, autoscaling
        └── tests/      # module tests (backend and frontend configurations)
```

`ecs_service` is the reusable module, called twice. Two optional inputs make the difference between the tiers:

| Input | Frontend | Backend |
|---|---|---|
| `load_balancer` | ALB blue target group | `null` (private) |
| `service_connect` | `null` (client only) | `{ dns_name = "backend" }` (published) |
| `command` | image default | `flask db upgrade && gunicorn …` |
| `secrets` | none | `DATABASE_URL` |

## Deploying

Run all commands from PowerShell. Expected repository layout:

```
3-tier-app-ECS/
├── Infra/       # this folder
├── frontend/    # from frontend.zip
└── backend/     # from backend.zip
```

### 0. If the 2-tier stack is still running, destroy it first

```powershell
cd Infra
terraform destroy
```

The ALB target group changes port (5000 → 80), which forces it to be replaced. AWS won't delete a target group while a listener still uses it, so updating in place fails. A clean destroy avoids that.

### 1. Init and create the two ECR repositories

```powershell
terraform init      # new modules: ecs_cluster, ecs_service
terraform apply `
  -target="module.frontend.aws_ecr_repository.this" `
  -target="module.backend.aws_ecr_repository.this"
```

The services need images to exist, so the repositories come first. The `-target` warning is expected.

### 2. Build and push both images

```powershell
cd ..
$ECR = "344707019777.dkr.ecr.us-east-1.amazonaws.com"
$TAG = git rev-parse --short HEAD

aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin $ECR

docker build --platform linux/amd64 -t "$ECR/ecs-3-tier-app-backend-ecr:$TAG"  .\backend
docker push "$ECR/ecs-3-tier-app-backend-ecr:$TAG"

docker build --platform linux/amd64 -t "$ECR/ecs-3-tier-app-frontend-ecr:$TAG" .\frontend
docker push "$ECR/ecs-3-tier-app-frontend-ecr:$TAG"

$TAG   # put this tag into terraform.tfvars
```

### 3. Set the image tags and apply everything

In `terraform.tfvars`, replace `<git-sha>` with `$TAG` in `frontend_image` and `backend_image`. Then:

```powershell
cd Infra
terraform apply
```

The apply pauses at the ACM validation step if the certificate is new. Create the CNAME from `terraform output acm_validation_cname_name` / `acm_validation_cname_value` at your DNS provider. If the record is still there from before, validation completes on its own.

The backend runs `flask db upgrade` on every start. That's idempotent, and it creates the `topics`, `questions` and `wiki_pages` tables.

### 4. Load the quiz questions (once)

```powershell
.\scripts\seed-db.ps1
```

This runs a one-off Fargate task from the backend task definition. It loads `seed_data.py` and the CSVs in `questions-answers/` (AWS, Docker, Jenkins, Kubernetes, Linux). Exit code `0` means success. Running it twice adds duplicate questions.

### 5. Open the app

`https://quiz-app.stev6devops.2bd.net`. Your DNS CNAME should point to `terraform output load_balancer_dns_name`.

## Troubleshooting

| Symptom | Check |
|---|---|
| 503 from the ALB | The frontend has no healthy tasks. `aws ecs describe-services --cluster ecs-3-tier-app-cluster --services ecs-3-tier-app-frontend-service --query "services[0].events[0:5].message"` |
| Page loads, but topics are empty or show an error | Proxy or backend problem. `aws logs tail /ecs/ecs-3-tier-app-frontend --since 15m` shows `Proxy error: …` lines |
| `Proxy error: getaddrinfo ENOTFOUND backend` | The frontend tasks started before the backend was published. Run `aws ecs update-service --cluster ecs-3-tier-app-cluster --service ecs-3-tier-app-frontend-service --force-new-deployment` |
| Backend tasks keep stopping | `aws logs tail /ecs/ecs-3-tier-app-backend --since 15m`, usually a migration or database connection error |
| Topics list is empty, no errors | The database hasn't been seeded. Run step 4 |

Service Connect (Envoy) logs are in the same log groups, under the `service-connect/` stream prefix.

## Tests

```powershell
terraform test                                  # whole stack, mocked AWS
cd modules\ecs_service; terraform test; cd ..\.. # the service module, both configurations
```

These run a full `plan` against mocked providers. No AWS credentials are needed and nothing is created. They check the wiring: which service is behind the ALB, which is published in Service Connect, the secrets and the command override.

## Notes

- **Image updates:** the task definitions ignore `container_definitions` changes, so the CI pipeline owns the image tag after the first deploy. Bumping `*_image` in tfvars after that has no effect. Deploy new images through the pipeline (or register a new task definition revision) instead.
- **Cost (dev, roughly per day):** NAT gateway around $1.10, ALB around $0.55, RDS `db.t3.micro` around $0.40, and 2 Fargate tasks at 0.25 vCPU around $0.50. Run `terraform destroy` when you're not using it. Service Connect itself has no charge.
- **Service Connect scope:** only services in this cluster's namespace can resolve `backend`. Nothing outside the VPC can.
